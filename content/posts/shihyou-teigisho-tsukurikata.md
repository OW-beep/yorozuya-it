## 数字が合わない原因は、「定義の違い」

会議で、「担当者によって、数字が違う」という場面は、珍しくありません。その原因は、計算のミスではなく、**同じ言葉を、違う意味で使っている**ことであることが、少なくありません([データ分析の前に決める4つのこと](/posts/data-bunseki-mae-4tsu))。

この問題を防ぐために役立つのが、**指標の定義書**です。指標ごとに、「何の判断に使うか」「どう数えるか」を、1行にまとめた台帳です。

## 定義書に書く項目

| 項目 | 内容 | 書き方の例(購入顧客数) |
|---|---|---|
| 指標名 | 誰が見ても、意味が分かる名前 | 購入顧客数(月次) |
| 目的 | 何の判断に使うか | 販促の効果を確認する |
| 定義 | どう数えるか | 対象月に、1回以上購入した顧客の人数 |
| 集計期間 | 期間の区切り | 毎月1日〜末日 |
| 対象 | 含めるもの・除くもの | 含める:通常の購入 / 除く:キャンセル・返品済み・テスト用の注文 |
| 重複・例外 | 同じものを、どう扱うか | 同じ顧客が複数回購入しても、1人と数える |
| データの出所 | どこから取るか | 受注システムの注文データ |
| 更新タイミング | いつ確定するか | 月初に前月分を確定 |
| 担当者 | 定義に責任を持つ人 | (担当者名) |
| 最終見直し日 | いつ確認したか | 2026/10/01 |

特に、**「目的」と「対象(除くもの)」**は、省かれがちですが、重要です。目的が分かれば、定義の妥当性を判断でき、除くものを書いておけば、例外の扱いでぶれません。

## 例:「顧客数」を3つに言い分ける

「顧客数」という言葉は、複数の意味で使えます。意味が複数あるなら、**名前を分けて、別の指標として書き**ます。

| 指標名(おすすめ) | 定義 | 使う場面 |
|---|---|---|
| 購入顧客数(期間内) | その期間に、実際に購入した顧客の人数 | 販促の効果、売上の動きの確認 |
| 登録顧客数(累計) | 購入の有無にかかわらず、登録されているすべての人数 | 会員基盤の大きさの把握 |
| ユニーク購入顧客数(重複除外) | 同じ顧客が複数回購入しても、1人と数えた人数 | 顧客一人あたりの購入額の算出 |

「顧客数」という一つの言葉に、すべてを押し込まず、**意味ごとに名前をつける**だけで、会議での誤解が大きく減ります。

## 作り方の手順

1. **よく使う数字を、洗い出す**:会議や報告書に出てくる数字を、10個前後あげる
2. **1つずつ、目的を書く**:その数字で、何を判断しているのかを確認する
3. **定義・期間・対象・重複を書く**:言葉で、はっきり書く
4. **例外を、先に出す**:キャンセル、返品、テストデータ、社内利用などの扱いを、決める
5. **食い違いが見つかったら、名前を分ける**:同じ言葉で意味が複数あるなら、別の指標にする
6. **担当者を決め、関係者で合意する**:業務側と技術側が、一緒に確認する
7. **1か所に置き、変更履歴を残す**:誰でも見られる場所に、保管する

## 合意を取る時のコツ

- **業務側の人を、必ず入れる**:技術的に計算できることと、業務上それで意味が通ることは、同じではありません
- **例から始める**:抽象的な議論より、「このケースは、数えますか?」と、具体例で確認するほうが、合意しやすくなります
- **完璧を求めない**:最初は、「いまの定義」を書き、後から見直す前提で進めます

## 記入例:「売上」にも、複数の意味がある

「顧客数」だけでなく、「売上」も、定義がぶれやすい言葉です。次のような違いが、数字に影響します。

| 論点 | 例 |
|---|---|
| 税の扱い | 税込か、税抜か |
| 返品・キャンセル | 売上から、差し引くか。いつの時点で、差し引くか |
| 計上のタイミング | 注文した日か、出荷した日か、入金された日か |
| 値引き・ポイント | 値引き後の金額か、定価か |

これらを定義書に書いておくと、「売上が合わない」時の確認が、早くなります。**「何を、いつの時点で、どの金額で数えるか」**を、はっきり書くことが基本です。

## AIやExcelに集計を頼む時の依頼文

定義書があれば、集計を頼む時の説明も、簡単になります。

> 次の定義で、購入顧客数を月ごとに集計してください。定義:対象月に1回以上購入した顧客の人数。キャンセル・返品済み・テスト注文は除く。同じ顧客は1人と数える。
> 【データの項目】顧客ID、注文日、注文状況

結果は、一部を手計算で確認してください。「AIが出した数字」は、そのまま確定情報としては扱わない、という姿勢が大切です([AIの嘘を見抜く5つの方法](/posts/ai-uso-minuku-houhou))。

## 運用のコツ

| よくある失敗 | 対策 |
|---|---|
| 作って、置きっぱなしになる | 見直す時期(半年に1回など)と、担当者を決める |
| 部署ごとに、別の台帳がある | 台帳は、1か所にまとめる |
| 計算式だけで、目的が書かれていない | 「何の判断に使うか」を、必ず書く |
| 定義を変えたのに、周知されない | 変更日と理由を記録し、関係者に伝える |

数字が食い違った時は、**定義・期間・対象・重複・更新時期**の順に、台帳で確認します。AIやExcelで集計する時も、定義書の内容を、そのまま依頼文に入れると、数え方のぶれを防げます([ExcelでAIに関数を書かせるコツ](/posts/excel-ai-kansu-kakaseru-kotsu))。

## まとめ

- 数字が合わない原因は、**計算ミスより、定義の違い**であることが多い
- 定義書には、**目的・定義・期間・対象・重複・出所・更新・担当者**を書く
- 意味が複数ある言葉は、**名前を分けて、別の指標**にする
